# 论文四技能：独立用，也能串联

版本：检索 1.3.1、下载 1.3.1、解析 1.4.0、论文公众号 1.4.1（合集 1.9.1）。唯一维护源是 Arborseek/arborseek-skills。

文章配图按最终出现顺序连续编号，不沿用原论文图号；封面和公式不占号。原图号保留在内部溯源记录，正文图号引用按 visual ID 关联，旧稿写死的引用需逐一核对。

论文公众号新增独立公式 PNG 渲染：简单符号保留文字，复杂公式核对后登记 formulas 并放置正文图位。可选 Matplotlib 只在有公式时使用，超宽或不支持语法明确失败，详见技能内 references/formulas.md。前三步无需升级即可衔接。

论文公众号默认交付成稿：简短图注，文末集中出处，核查/权限/页码等留在内部档案。默认 render 执行成稿检查；`--draft-images` 只是内部预览，不能当最终文章交付。旧 article.json 的长图注需编辑为简短中文 caption，原始 paper_figure 记录保留，不改审核状态来跳过实际核查。

## 安装

- 通用四技能 ZIP：解压后，每个英文技能目录都是一个完整技能，放到实际宿主技能目录；不要把四个合成一个 SKILL.md。
- WorkBuddy 四技能 ZIP：先解压外层，再分别上传里面四个带中文名称的 ZIP；每个内层 ZIP 的根目录直接包含 SKILL.md。
- 支持按标准技能格式部署到 OpenClaw、Codex、Claude Code、Hermes Agent、WorkBuddy。实际路径与宿主工具差异以宿主当前配置为准；不自动安装依赖，不自动发布。

## 直接这样使用

单独使用：

- “检索 10 篇关于多模态推理的 arXiv 论文，只给清单。”
- “下载 1706.03762v7 的 PDF，不下载源码。”
- “解析这份 PDF，保存笔记和用到的论文原图，不写公众号。”
- “把这份 PDF 写成公众号，优先论文原图；没有合适原图再补示意图。”

串联使用：

> 检索关于〔主题〕的论文，按〔标准〕选一篇，下载明确版本，解析并保存原图，再写成中文公众号草稿。沿用同一资料目录，不重复取图，不自动发布。

中途接入：

> 接着这个论文资料目录写公众号，先校验并复用已有原图，只补读支撑文章需要的内容。

用户已有旧 Markdown 笔记也可接入，由助手整理已有证据，不要求手填 JSON。只问一个问题时不用强行跑完整流程。

项目网站资料：

> 检查论文链接的项目网站，把与解读有关、公开允许下载的图片、演示视频和补充 PDF 保存到这篇论文资料目录。单文件超过 50 MiB 先告诉我大小；不能下载的只记链接和原因。后续写公众号优先复用，不自动发布。

## 保存什么

每篇/每版本独立资料目录，包含 paper.pdf、paper-workspace.json、reading.md、figures/；从检索/下载接入时还可保留原检索记录与下载元数据。写作增加 article.json、HTML 与 assets/。

网站素材另存 project-assets/，索引为可选 project_assets 数组，区分 saved、link-only、failed。每项记录源页面/文件链接、取得日期、文件哈希、对应论文身份及使用说明；网页版本默认未核验。视频不自动解码或提帧；用宿主工具导出截图后，可登记父视频 ID、哈希与秒数。写作只采用明确选择的图片并标“项目网站素材，非论文原图”，不会把所有视频/PDF 自动插进文章。

原图索引记录图号、页码、图注、PDF 哈希/版本和图像哈希；再次取同图返回 cached。文件损坏、版本冲突和缺图明确报出，不以生成图补成“原图”。整份目录一起移动，不能只复制 JSON 或 HTML。

解析和论文公众号各自带 paper_workspace.py，不依赖对方安装。capture 使用已经安装的 Poppler pdftoppm；没有时使用宿主 PDF 导出能力并 import-figure。没有任何可用渲染/图片能力时，明确交付缺口，不能保证完成取图。

图片保存、视觉核对、使用权、科学结论和平台发布分别检查。内部草稿可显示带警示的候选图，最终 --require-ready 仍会阻止未就绪素材。这里的“最终检查通过”也不等于已经通过微信后台预览或完成发布。
