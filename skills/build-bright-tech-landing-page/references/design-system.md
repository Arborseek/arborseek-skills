# 设计参考：明亮科技风

这是默认方向，不是每页必须满足的参数表。优先用户品牌、现有设计系统和实际信息密度；冲突时说明取舍，不强行套用。

## 视觉与内容

- 默认白色或浅蓝灰底、深色正文、一个明确强调色。无品牌系统时可从背景 `#ffffff`、辅助底 `#f4f9fd`、正文 `#10263f`、次要文字 `#65768a`、强调色 `#0968eb` 起步，仍须检查实际文字与背景的对比度。
- 工程感来自信息、流程和真实场景，不来自霓虹、AI 大脑、漂浮标签与装饰网格。
- 先讲清“为谁、解决什么、下一步做什么”。没有可信案例或数据就省略证明区，不编造背书。
- 不预设 6–9 个区块。短活动可只有首屏、说明与报名入口，复杂产品再增加方案、流程和证据。

## 排版与布局

- 中文优先 PingFang SC、Microsoft YaHei、sans-serif 等系统字体组合，英文沿用已有或通用字体，不必下载商业字体。
- 大标题通常 600–700 字重，正文约 16px、1.7–1.9 行高作为起点；大屏首屏约 48–76px、段落标题约 32–52px。使用流式字号，检查长标题，不机械固定。
- 桌面容器可从 1200–1440px 起步，手机边距约 18–24px；已有规范优先。分栏考虑 `minmax(0, 1fr)` 与子项 `min-width: 0`。
- 长 URL、英文和代码需换行或局部滚动，不能用全局隐藏溢出来掩盖布局错误。
- 首屏可左文右图，也可根据素材与用户要求居中、纵向排列。平板和手机按可读性收列，不为固定断点压缩文字。
- 中英文切换覆盖按钮、图注、导航和弹层；页面太长时减少无信息价值的内容。

## 模块与配图

| 信息类型 | 可选结构 |
| --- | --- |
| 痛点与取舍 | 编辑式列表、对照说明 |
| 定义或定位 | 分栏叙述、关键事实 |
| 能力与应用 | 场景配图、非等权排列 |
| 数据 | 指标行与有依据的图表 |
| 流程 | 标明输入、阶段与输出的步骤 |
| 行动入口 | 简明总结、服务选项、一个主要行动 |

- 不让每段都成为“图标＋标题＋正文”的同款卡片；图标不用于填空。卡片可从 8–16px 圆角、轻边框、24–32px 内边距起步，无操作的卡片不要假装可点击。
- 优先用户素材、真实产品界面、工程团队和业务场景。先看原图再选 `object-position`，不用大面积蒙层盖住主体。
- 装饰图 alt 可为空，有信息价值的图片需有意义的 alt；保留比例、二维码静区和主体，不做无意义悬停放大。
- 数据图只用已验证数据，自绘流程或概念图标明示意；生成图片不得制造客户案例、实拍证据或指标。

## 导航、动作与动效

- 导航保持清楚的当前位置和键盘焦点；手机菜单按钮有可理解名称、`aria-expanded` 和关联目标。
- 普通展开式导航不是模态弹窗，不加错误的 dialog 角色或焦点陷阱；真正模态窗口才处理背景不可操作、焦点进入/返回、Escape 和关闭按钮。
- 首屏通常一个主要行动和一个次要链接即可；链接有真实目的地，按钮执行真实动作。
- 默认小幅、一次性入场，约 0.3–0.8 秒；避免持续呼吸、旋转、无意义悬浮。没有动画也可以是正确结果。
- 减少动画设置下禁用非必要动画和平滑滚动。JS 初始化失败时内容与链接仍可见，不先隐藏全部正文再依赖动画库显示。
