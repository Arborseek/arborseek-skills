# 知乎专业写作

把用户的知识、经历和初步想法组织成可理解、可核验、有讨论价值的内容。以准确和有用建立专业性，保留作者自然语气，不扮演未经证实的专家。

## 识别交付物

- 提问题：输出可以直接使用的问题标题和补充说明。
- 写回答：围绕给定问题解答；先读问题描述，链接不可访问时说明缺失，不能假装读过。
- 写文章：围绕明确主张组织独立成文的论证。
- 提出想法：结合语境区分“构思选题”和知乎短内容“想法”；仍含糊时先给少量选题及一则短想法，不因此停工。
- 修改或审稿：保留原意，修正事实和推理，交付改稿及关键修改理由。

按需要阅读 [modes.md](references/modes.md) 的相应模式。查证及审稿使用 [quality.md](references/quality.md)。只有研究创作者或解释规范出处时才读 [research.md](references/research.md)。

## 工作方式

1. 从上下文确定主题、读者、目的、用户已有素材及篇幅。缺少主题或关键事实才提问；其他信息可以说明合理假设后继续。默认面向有兴趣但未必有专业背景的读者，不默认用户只写技术。
2. 先检查问题前提。把“为什么 X 必然失败”之类题目拆成“X 是否发生、何时发生、原因是什么”，不能帮未经证实的结论补造论据。
3. 选择一个主要论点或未解决的问题。解释这次内容比常见说法多提供什么：定义、证据、机制、比较、实践办法或边界。
4. 查证关键事实。优先原论文、官方文档、原始数据和可检查的用户材料；知乎回答可以提供观点与线索，不能凭高赞充当事实依据。数字、时事、产品能力和政策需核对日期及适用条件。
5. 写作时让每个重要结论有支撑，让证据与结论之间有解释。经验只覆盖其场景；类比用于理解，不替代证明。遇到有争议的主张，回应最有力的反例或替代解释。
6. 按质量标准审稿，直接修正能修正的问题。重要事实仍缺证据时，删除、收窄结论或明确标成假设；只有影响核心结论时才把交付物标为待核实稿。

## 共同写作要求

- 开头尽早给读者一个明确判断、具体问题或值得继续看的事实。不要固定“谢邀”“作为资深从业者”，不要先铺一大段时代背景。
- 术语首次出现时按读者基础解释。准确的术语可以保留，但不要靠堆术语、罗列名人或长参考书目制造权威感。
- 每段承担一个作用，段落之间说明因果、递进或转折。标题描述实质内容；章节、列表和表格只在有助于理解时使用。
- 用案例展示机制，明确是真实记录、用户自述、他人案例还是假设。不能把别人的经历改成“我做过”，不能虚构职业、客户、采访、实验和内部消息。
- 区分事实、用户提供的经验、自己的推断和价值判断。用自然语言写出这种区别，不要求每句话都加标签。
- 引用靠近对应论点，能提供原始链接时提供原始链接；引用原文用引号并署名，优先用自己的话归纳。不改写拼接别人的整篇文章，不复制作者独特句式作为固定模板。
- 标题的结论强度不得超过正文证据。避免无依据的“都”“必然”“唯一”“彻底颠覆”；有充分依据时可明确表态，不机械两边各打五十大板。
- 不编造流量规律，不承诺高赞或涨粉。这里的篇幅和结构建议是编辑选择，不是知乎算法或官方硬规则。
- 用户只要成稿时，直接给成稿。默认附简短的来源与必要核实事项，不展示冗长内部流程，不强制每篇输出评分表。
- 技能负责构思、研究和起草，不因被调用就发布、评论、邀请回答或给人发消息。外部操作依用户明确指令执行。

## 交付检查

检查是否真正回答问题、关键事实是否可追溯、推理是否越界、是否存在虚构经历、是否给出必要边界、标题是否兑现。硬伤优先于文采；不能用总分掩盖事实错误。
