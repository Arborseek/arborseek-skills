# 五种内容模式

以下是编辑建议，可按用户目的调整，不是平台规定。不要把所有结构同时塞给用户。

## 提问题

先搜索近义问题，判断是否已有相同对象和条件的问题；无法搜索时说明未查重。已有问题能承载讨论时建议补充该问题；确有不同对象、条件或证据缺口再另拟。

标题只承载一个核心疑问，提供必要对象和条件，读者不看补充说明也能理解。补充说明交代背景、已知信息与来源、已尝试或已比较的路径、具体卡点，以及希望什么证据能够回答。私密信息应去标识化。

默认给一个推荐标题和一段完整说明；需要选择时再给两个不同角度的备选。话题标签给少量相关建议，并标明未验证其在平台是否存在。

示例（假设场景，不代表用户实际情况）：

- 太宽：机器人怎么落地？
- 预设结论：为什么机器人落地都不行？
- 更好：评估室内巡检机器人的试点效果，除了任务完成率，还应记录哪些人工干预指标？
- 补充说明：希望比较人工巡检和机器人试点。关注相同路线、巡检项目与时段下的结果，想了解接管次数、接管时长和漏检情况应如何定义与记录；不讨论尚未提供证据的商业收益。

对比型提问写明目标和约束，不泛问“A 和 B 谁更好”。经验型提问邀请回答者说明场景与限制，避免只征集成功故事。机制型提问先确认现象，不把个案当普遍规律。

## 写回答

开头先回答题目；前提有误时温和澄清，然后回答修正后的问题。可采用“判断及条件 → 原因 → 证据或例子 → 反例/边界 → 可行动建议”，不必每项都设置标题。

- 知识解释：定义、机制、直观例子、常见误解。事实性解释优先一手材料。
- 决策比较：先定义选择目标，再比较同一组维度，说明不同条件下推荐为何变化。
- 经验分享：背景、采取的行动、实际结果、其他可能影响因素、可迁移部分。没有实测就明确未实测。
- 热点评论：拆开已确认事实、争议事实和自己的判断，回应对方最强论据，不猜测动机。

已有回答可用于识别讨论缺口；不为了差异化刻意唱反调。短问题可以短答，能够一句话说明的结论不扩成伪深度长文。

## 写文章

先确定目标读者和一句话主张。默认直接交付标题及全文，只有用户要大纲或核心素材不足时才以提纲为主要交付。

可选组织方式：

- 教程：读者前提与完成目标 → 最小例子 → 原理和步骤 → 检验办法 → 常见失败与适用边界。
- 分析：具体问题 → 可检验主张 → 按论证组织证据 → 替代解释 → 条件化结论。
- 复盘：初始目标与基线 → 实际操作 → 结果与偏差 → 归因限度 → 下一步。

标题描述读者所得，摘要在确有需要时提供。示例标题：“如何记录巡检机器人的人工接管：一份试点评估设计”。正文必须真的提供记录方案，不能只讲行业趋势。

一篇文章优先解决一个主要问题。数字图表要注明来源、单位、统计范围；概念图或假设数据必须标明性质。配图用来减少理解成本，不能代替正文中的证据。

## 构思选题

从读者的真实决定、反复出现的误解、方案取舍、失败复盘、数据矛盾和方法边界切入。用户未给数量时优先给 3–5 个有区别的方向。

每个方向写清：谁有这个困惑；核心问题/暂定观点；内容增量；现有素材；缺什么证据；适合提问、回答、文章还是短想法。没有搜索对比时不声称全网首创。

用“重要性、素材可得性、作者真实经验、证据成本”做定性取舍。推荐最值得先做的一项并给开头或问题草稿，不能只列十个标题。

## 知乎短想法

一个具体观察、一点自己的解释、一个值得继续讨论的问题即可。默认约 100–300 字，按内容调整；这不是平台字数限制。可表达尚未成熟的假设，但必须说清是猜想。不能把复杂争议压缩为没有依据的绝对判断。

原创示例（方法建议，非实测结论）：

“评估巡检机器人的演示，我会额外记录一个数字：人接管了多久。任务最终完成，并不能单独说明其中多少工作由机器人承担。若在相同任务下，同时记录自主完成情况、接管时长和异常类型，后续比较会更清楚。你们在试点中怎样定义‘人工接管’？”
