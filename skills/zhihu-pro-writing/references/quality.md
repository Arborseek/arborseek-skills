# 证据与专业性检查

## 核查重要论断

研究型任务可在工作记录中维护：论断、材料出处、发布日期/版本、材料直接证明什么、仍不能证明什么。最终稿只保留读者需要的引用和边界。

- 数字：核对分母、单位、时间、样本选择及比较基线。百分比与百分点不可混用。
- 因果：先辨别相关、时间先后与因果识别；存在混杂时不要写成“证明了”。
- 比较：保持对象、任务、成本口径和测量条件一致；不同榜单或不同实验不能简单拼成排名。
- 技术/科研：记录版本、实验条件及任务定义；论文宣称、独立复现、用户实测、生产验证分开表述。
- 经验：说明是个人/单项目观察；无采样依据不得改成行业普遍现象。
- 预测/建议：明确假设、依据和会使判断改变的条件。
- 热点与动态规则：检索当前原始来源。搜索摘要只作线索，读不到全文时限定依据，不能捏造引文或把摘要当全文。

链接存在不代表支持论点，必须核对对应段落。转述不能把原作者的“可能”升级为“必然”。检索不到时可给提纲、证据需求或收窄后的稿件，不为凑参考文献生成假 URL。

## 去除伪专业写法

| 待修改表达 | 更可靠的处理 |
| --- | --- |
| 据权威数据显示，效果提升 80% | 补出真实来源、指标、基线和条件；没有则删掉数字 |
| 我从业十年，见过上百个项目 | 只有用户明确提供真实经历才保留，否则去掉身份背书 |
| 这个结果证明所有企业都应该采用 | 说明样本与适用场景，把结论收窄到证据能支持的范围 |
| 涉及多模态认知闭环和系统级赋能 | 具体说系统接收什么、做什么决定、如何检查结果 |
| 某大 V 都说了，所以肯定正确 | 回到原始材料，分析其论据，不把作者名气当证明 |

## 审稿维度

按“满足 / 需修改 / 不适用”检查，通常内部完成；用户要求评审时才展示。

1. 相关性：读完能否回答题目中的实际疑问？
2. 准确性：关键数字、引用、经历和来源能否核对？
3. 推理：证据如何支持结论，是否有跳步或概念偷换？
4. 边界：重要条件、反例和替代解释是否得到适当处理？
5. 增量：读者获得了什么新理解或行动办法？
6. 可读性：没有专业背景的人能否跟上，专业读者能否复核？
7. 标题兑现：标题是否超出了正文结论或承诺？

伪造事实/身份/来源、错误前提和结论明显超出证据属于硬伤，不能以文采或其他项目得分抵消。不能把所有文章机械改成论文，主观审美与个人感受无需强行添加统计引用。

## 平台规范边界

本技能是编辑规范，不是知乎官方规则的全文或最新摘要。研究记录提供官方指南入口。只有用户询问具体规则或要求发布检查时，再核查相应现行规则，包括必要的 AI 内容标识要求；不能把历史页面、第三方运营建议或本技能的篇幅建议说成官方要求。
