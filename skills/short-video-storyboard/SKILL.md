# 短视频脚本与分镜助手

把一个工作选题变成员工能拍、剪辑能接的脚本。适用于视频号、抖音、小红书、B站等渠道的产品演示、知识科普、人物口播、操作教程、活动记录、客户案例、企业宣传和招聘文化内容。也能把论文解读或公众号文章压缩成短视频，不要求安装其他技能。不负责实际生成视频、登录平台或发布。

## 先决定怎么拍

从现有对话/素材提取：视频要达成什么、给谁看、主题、预计时长、渠道/画幅、出镜者、现有场地和素材、人员设备、需要保留的事实。缺少关键信息时集中问一轮，通常不超过三个问题；普通选题可直接给初版，说明少量制作假设，不要求用户填写 JSON。

没有要求时，以 45–60 秒、竖屏 9:16、单人手机+现有工作场所作为低成本制作假设，不声称这适合所有平台或是平台规定。用户说横屏、长视频、不出镜、只有旧视频时覆盖默认。平台当下时长限制、热门玩法或热点需要查证，别把经验值写成平台政策。

按 [类型选择](references/types.md) 选择一个主类型，可以组合一个辅助类型，不将八套模板全部输出。每条视频只承担一个核心传播目标；连载选题可拆成多条独立脚本。CTA（希望观众做的下一步）服务目标，不默认引导加私域或购买。

## 写作与分镜

1. 开头用可见的问题、操作结果、现场动作或准确的反差引出主题，不承诺“必爆”，不用虚假的焦虑、极限词或故意隐藏重要条件。
2. 先写顺口的口播，再为每段安排能拍到的画面。旁白、同期声、采访回答、字幕不是同一列；采访只写问题与回答要点，未采访不能编受访者原话。
3. 分镜必须说明主体、动作、场景、景别、机位/运动、时长、声音、字幕与素材来源。避免只有“高级感画面、科技感转场”等不能执行的词。转场可用动作衔接/直切，不强制每镜炫技。
4. 主镜头（人物/演示）负责信息，补充镜头（手部、细节、环境、屏录）提供证据和遮盖剪辑点。不要求每句换镜头；单人口播可长镜头拍摄，剪辑时穿插补画面。
5. 根据用户可用资源写方案：单人拍摄用固定机位和可重复动作；多人调度、航拍、特殊场地、复杂灯光仅在资源允许时提议，并给低成本替代。不出镜可用屏录、手部特写、素材配音，不能偷偷改成数字人。
6. 每个镜头分配时间，总时长包括停顿、操作、现场声和结尾；先实际试读，超时就删减或拆条，不能只加快语速。中文每秒约 3–4 字仅为估算起点，英文、公式和专业词另留解释时间。

涉及详细拍摄、旧素材、论文/文章改编、剪辑交接时读 [制作与交付](references/production.md)。不做画面生成；如另有生成或剪辑请求，再调用宿主适合的工具，并明确本轮是否真的产出了视频。

## 员工交付包

默认交付一份主方案，用户要求时再增加不同开头或时长版本：

- 选题定位：标题、受众、目的、类型、时长和拍摄假设。
- 可直接试读的口播/旁白稿，不把拍摄提醒或核查信息混进去。
- 分镜表：镜号、时间段、景别/机位、画面动作、口播/同期声、屏幕字幕、音效/音乐、所需素材。按文章/视频内实际顺序编号。
- 执行清单：人员、场地、道具、镜头拍摄顺序、需补素材、剪辑要点。制作待办单独放，不出现在观众字幕里。

用户只要口播稿或现成稿改分镜时，缩小交付范围，不强行产出全套材料。需要员工协作表或粗剪字幕时读 [结构与导出](references/schema.md)，由助手整理内部 JSON 后运行：

```bash
python3 scripts/storyboard.py check /实际任务目录/storyboard.json
python3 scripts/storyboard.py export /实际任务目录/storyboard.json /实际交付目录
```

导出 script.md、shots.csv、rough-subtitles.srt、production.md、manifest.json。SRT 是按分镜计划估算的粗剪字幕，不是已对齐录音的成片字幕；没有人声的镜头可留空字幕。脚本只检查结构、时长和明显占位词，不证明事实、版权、口播节奏或成片可用。

## 事实与发布边界

功能参数、对比测试、价格、客户效果和论文结论要有用户提供或实际查到的依据。未知时用不依赖该事实的表达；必要的待确认项放制作清单，不把“待补数据”写进可用口播。不要给客户编证言，不把摆拍当真实纪实，不把推测冒充实验结果。标注演示环境、研究范围等会影响理解的条件。

员工/客户肖像、客户名称、屏录账号、生产现场和聊天内容在对外使用前按实际情况确认；提醒打码或换成演示数据，不自动翻查同事私人材料。危险设备操作由合格人员完成，不为了镜头安排高风险动作。音乐/图库仅提供风格建议或已有合法素材，不能保证“全网音乐都可商用”。

本技能不自动上传、群发、发布、创建定时任务，也不把生成脚本视为素材授权。可与论文、公众号和素材检索技能衔接，但独立输入主题/文稿/素材清单也能使用。运行环境与兼容边界见 [运行约定](references/runtime.md)。
