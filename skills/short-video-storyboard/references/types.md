# 类型选择

类型由传播目的决定，不是简单换标题。时长仅作制作建议，用户要求优先。

| 类型 / type | 工作场景 | 叙事与画面安排 | 注意事项 |
| --- | --- | --- | --- |
| 产品演示 / product-demo | 功能介绍、销售答疑、应用场景 | 一个真实使用问题 → 一次关键操作 → 可见结果 → 适用条件/下一步；常用全景建立场景、手部近景和界面录屏 | 不用未验证的效率百分比；真实拍不到效果时改成流程说明 |
| 知识科普 / explainer | 技术概念、行业问答、论文内容 | 一个问题 → 直觉类比 → 一个证据/例子 → 边界；口播+简图/原始资料 | 类比不等于机制，原论文实验条件不因压缩而消失 |
| 人物口播 / talking-head | 员工分享、专家观点、负责人答疑 | 先说结论 → 一个经历或证据 → 可操作建议；固定中景+必要补镜 | 第一人称经历必须来自本人，不能编“我亲历过” |
| 操作教程 / tutorial | 产品使用、员工培训、常见故障 | 完成目标与前提 → 按步骤做 → 验证结果 → 常见错误；屏录/俯拍操作 | 有风险步骤先提示；不把账号密码、客户名单录进去 |
| 活动记录 / event-recap | 展会、培训、沙龙、公司活动 | 现场亮点 → 发生了什么 → 参与者实际体验 → 后续行动；建立场景、互动、细节、同期声 | 以实际素材为准，错过的环节不能靠摆拍伪装现场 |
| 客户案例 / customer-case | 项目故事、行业方案、客户访谈 | 客户原问题 → 实际部署过程 → 有依据的变化 → 适用边界；采访问题+获准现场素材 | 待采访的回答不写成引语；客户名、效果与授权须核对 |
| 企业宣传 / company-story | 企业介绍、展厅介绍、业务说明 | 目标客户的问题 → 团队如何解决 → 能验证的工作片段 → 联系/了解入口 | 不默认喊口号、虚构资质或大场面；用普通工作细节说明能力 |
| 招聘与团队文化 / team-culture | 岗位介绍、员工一天、团队协作 | 真实工作任务 → 协作方式 → 岗位期待/团队体验 → 招聘入口 | 薪资福利工时以确认信息为准，员工出镜自愿，不做虚假招聘承诺 |

## 常用约束变体

- **不出镜**：教程走屏录，产品走手部演示，科普走原图/简图+配音，活动用获准现场素材。不能因为不出镜就加入虚拟客户证言。
- **只有旧素材**：先按素材内容与实际可用片段重建叙事，缺口用字幕/获准屏录补齐，不能先写一个完全拍不到的脚本。
- **单人手机**：优先固定机位；先一次录完整口播，再补近景；列出必须拍的镜头和可省略镜头，压缩来回换场。
- **一条拆多条**：每条单独交代问题和结论，避免第二条只剩断章取义的实验数字。
- **多平台**：核心事实共用；按用户目标调整信息密度、标题和画幅，不凭空承诺平台流量效果。
