# 跨平台运行约定

适用：OpenClaw、Codex、Claude Code、Nous Research Hermes Agent、WorkBuddy。
三个技能共享文件格式与数据交接，不共享各应用的权限、会话或调度状态。
首次执行、切换机器/沙箱或工具缺失时读取本文件；无需每轮重复检查。

## 发现与加载

- 以宿主实际提供的技能列表和 SKILL.md 位置为准。核心入口仅用通用 YAML 的 name、description、metadata；agents/openai.yaml 只供 Codex UI 使用，不作为执行入口。
- 通过宿主技能加载机制调用同套件技能；名称是 tianshu-tanjie-paper-search、tianshu-tanjie-arxiv、tianshu-tanjie-paper-reading。不把 Codex 的美元符号调用方式当作其他平台的必需语法，也不要将技能名称当 shell 命令。
- 相对 references/ 和 scripts/ 都相对当前 SKILL.md 所在目录，不相对终端工作目录。找不到附件时报告安装不完整，不能虚构其内容。
- 在远程机器、容器或沙箱内运行时，使用该执行环境可见的技能目录和文件路径。宿主机路径不能直接假定在容器内存在。

## 运行能力

检索与下载脚本需要 Python 3.9+、终端执行权限及官方 arXiv HTTPS 访问能力；保存结果还需可写目录。解析已提供的文本不必具备这些脚本条件。

1. 从宿主可用命令中选择解释器：macOS/Linux 通常 python3；Windows 通常 py -3 或 python。用版本查询确认，不擅自安装解释器或修改 PATH。
2. 保留 -X utf8 参数，让中文 JSON 在不同系统默认编码下可读。所有路径作为单独参数传递并按当前 shell 正确引用；优先工具的参数数组能力。SKILL.md 中复杂查询示例适用于 POSIX shell/PowerShell，不原样套用到 Windows cmd 的单引号规则。
3. 搜索可先执行 scripts/search.py --keywords transformer --dry-run；下载可执行 scripts/arxiv.py --help。它们不请求网络。测试成功只表示程序可启动，不代表网络或 PDF 阅读已就绪。
4. 输出目录属于当前任务，不写进技能安装目录。相对 outputs/、work/ 是建议；宿主已有规则或用户指定路径优先。网络磁盘/特殊文件系统如不支持硬链接，当前脚本的无覆盖发布会安全报错；改用获准的本地输出目录，不改为覆盖写入。
5. 请求间隔由单进程控制。两脚本之间仍须串行访问 arXiv，不能通过同时启动多个应用绕过限流。

## 缺少能力时

| 缺失能力 | 可继续做什么 | 不应声称什么 |
| --- | --- | --- |
| Python 或终端 | 用已可用的官方网页工具有限检索；交付查询方案或手动下载链接 | 脚本已执行、文件已保存 |
| 网络 | 处理已有 JSON、PDF 或正文；离线构造查询 | 已获取最新检索结果 |
| PDF 文本提取 | 用已有正文或对应版本官方 HTML；否则请求正文/可读副本 | 已精读未读取的 PDF |
| 图片查看或 OCR | 分析可提取文字，并列出未核验图表/扫描页 | 已视觉核对图片、公式或扫描页 |
| 附件交付 | 返回实际保存路径与简要结果，说明远程/本地位置 | 用户电脑上已经有远程文件 |
| 原生调度工具 | 完成单次任务，说明尚未配置持续跟踪 | 已安排未来运行 |

只调用实际可用且被允许的工具，不通过提权、改配置、下载新软件或上传私有论文绕过缺失能力。必要的新授权由宿主正常流程处理。

## 可选调度与展示

- 定时跟踪不是三技能的安装副作用。用户明确要求后，查找宿主当前可用的原生自动化能力：Codex 自动化、OpenClaw 原生调度、Hermes 原生调度，或 Claude/WorkBuddy 当前版本提供的任务入口。名称只是路由提示，不是可直接执行的工具名。
- 不把任一平台的工具调用参数复制到另一平台；先读取当前工具说明。没有调度能力时不私自创建系统 cron。只有工具返回成功与任务标识后才报告已配置。
- 长期任务的运行环境必须也能访问技能、Python、网络和状态目录；本地安装不意味着远程调度器也已安装。
- 默认文本/Markdown 交付。使用宿主真实支持的附件或本地文件链接；不强制 Codex 面板、某浏览器、HTML 预览或本地服务器。HTML 是可选文件，不是核心功能依赖。
