# 从阅读笔记到公众号文章

## 叙事选择

用户未给结构时，可用“读者遇到的问题 → 旧方法的困难 → 新方法的直觉 → 最有解释力的实验 → 局限与适用对象”。按论文调整，不硬套。首段让读者知道为什么值得了解；结尾回到论文真正支持的结论，而非空泛的未来展望。

常见输入：“把刚解析的论文写成公众号，给工程师看”“这篇论文有什么价值，用原图讲清楚”“保留论文证据，语气通俗一点”。无需用户再选择一遍技术文章类型。默认 technical-paper、accessible、cyan-research，可按用户品牌修改主题。

解读不是逐句翻译；保留关键方法名便于原文检索。公式只留下解释机制必要的部分。比较结果写清基线、数据集、指标和条件；相对提升与百分点不混淆。未复现就不说“实测证明”。作者声称的贡献与编辑判断分开。

保留的复杂公式按 [公式排版](formulas.md) 生成可上传 PNG；简单变量留在行文中。检查未包裹 LaTeX 分隔符的纯文本等式，不要只扫描美元符号。公式前后解释符号和直觉，不把整段理论堆成公式墙。

## 发稿前审查

1. 标题、作者、版本、公开状态、官方链接一致；阅读范围字段只进内部记录。仅摘要/部分原文限制确实影响解读时用一句自然中文说明，不把 full-text / partial / abstract / notes-only 字段贴进正文。
2. 关键结论能回到原文定位；夸大词、版本差异、未见附录均已处理，关键推断可辨认。
3. 图文相邻，每个图有读者能理解的中文图注，原图、重绘和 AI 图身份不混淆；图注说明让读者看什么，不只是“如图所示”。
4. 使用依据、缺图和未核验项完整保存到内部记录。先解决、替换或省略不必要图位再交成稿；必要材料仍缺失就单独报告阻塞，不把带审核标签的预览冒充成稿。
5. 校验包、渲染、静态 lint 通过后才做桌面和手机视觉检查；最终简报分别写通过、失败、未验证。依赖缺失不等于通过。

## 输出边界

完整 UTF-8 HTML + assets/ 是默认排版交付，按需附 Markdown。若用户只要正文，直接交付中文稿，无需强行运行排版。若只要排版，保留已批准文字含义，不擅自加入新科学结论。

图注按文章实际顺序写“图 1｜一句说明、图 2｜一句说明…”，不沿用论文图号；封面和公式图不计数，删图和调序后同步文中引用。HTML 引用使用 handoff 约定中的 data-figure-ref，避免写死旧图号；Markdown、聊天直接成稿也手动核对连续编号。页码、裁剪、哈希、审核状态不出现在正文。文末集中列论文版本、链接与图片来源（同一来源合并），不在各图下重复整篇书目信息。Markdown 不输出 `&#x20;` 等转义残留。核验提醒只放交付简报，不混入可复制正文。

公开论文来源使用可点击超链接：HTML 的 a 标签 href 指向已核对的对应版本官方地址，文字显示论文标题；Markdown 用标准 Markdown 链接。不将链接写进代码块、不转义成文本标签。输出时检查 href，不声称微信后台一定保留外链功能。

不要自动在成稿里加入技能发布者作为论文作者或研究机构，不自动加公司广告。发布主体与论文作者明确分开。文章包和交接 JSON 是内部记录；用户需要编辑或追溯时才作为附加交付。
