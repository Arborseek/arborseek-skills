# 公众号公式处理

遇到数学表达式时读取本页。先判断表达需要，不把全文变量都变成图：A、Z、Y、α、x² 等简单行内符号保留文字，可用 sub/sup；独立推导、分式、求和、条件概率等用确定性排版生成 PNG。不要把 LaTeX 源码、美元分隔符或截图中那种长纯文本等式直接交付成稿。

## 核对与登记

从已核验的同版本论文转写必要公式，核对条件竖线、希腊字母、下标、括号与因子顺序；OCR 结果必须与原图对照。长公式在等号或乘积边界人工分行，不改变数学意义。公式不是 AI 概念配图，不要求无意义的“缺少原图”理由，也不标成“AI 生成”。如直接裁剪论文公式截图，则按既有 original 图片流程核对来源和使用依据。

在 article.json 顶层登记 formulas（也可随 handoff 传入），正文指定位置放一个空 p 标签：

```html
<p data-formula-id="eq1"></p>
```

```json
{
  "formulas": [{
    "id": "eq1",
    "latex_lines": [
      "p(A,Z,Y\\mid c)",
      "=\\pi(A\\mid c)\\,p(Z\\mid c,A)",
      "\\quad\\cdot p(Y\\mid c,A,Z)"
    ],
    "alt": "动作、未来状态与任务进展的联合概率分解",
    "locator": "填写实际核对的论文公式编号或页码",
    "checked": false
  }]
}
```

示例只展示排版结构，不替代论文核验。checked 只能在实际核对后修改。latex_lines 每行不带 $，JSON 中反斜线写成双反斜线。文中紧邻公式用一两句解释符号与含义，不加内部定位或审核字样。

## 本地渲染与降级

使用现有环境的 Matplotlib；缺少时在用户允许的环境按 requirements-math.txt 安装可选依赖。无公式时无需安装。默认 render 自动将登记公式生成白底深色、3 倍分辨率 PNG 并插回原位置，和其他图片一起保存到 assets/，保留 alt 和显示宽度；不依赖公众号执行 JavaScript、MathJax 或外部公式服务。

渲染器使用 Mathtext 支持的 TeX 子集，不启动 TeX 命令或 shell，不调用 AI 画数学。矩阵、aligned 等不受支持的语法会失败，不会自动删符号或改成普通文字。可按正确语义拆成 latex_lines，或用宿主已有可信公式渲染器生成 PNG 后走已核验图片流程；不要上传私有论文到在线公式服务。

超出约 342 CSS 像素的单行会报错，先分行而非缩到难读。保存后实际查看 PNG，并在约 390px 手机宽度检查上下标、根号、分数线、裁边与顺序；白底避免深色模式下透明黑字不可见。静态校验只能发现常见公式残留，不能识别全部数学或证明公式正确，助手仍须逐段检查独立等式。

公众号使用的是排版后的富文本，不是上传 HTML 文件。若粘贴后公式图丢失，从 assets/ 上传对应 PNG 到原位置；预览核对后才能说公式已在后台显示。此流程不自动发布。
